## New shared file: `activity1/shared/factor_labels.R`

Step 1 recodes the ordinal variables to integers and then calls `as.factor()`,
so the cleaned data carries bare digits as level names ("1"/"2"/"3", "0"/"1").
Since Step 1 is out of scope for this pass, the labels are restored **at load
time** in Steps 2 and 3 instead, by a small shared helper:

```r
source("../shared/factor_labels.R")
data <- apply_factor_labels(data)
```

- `company_size`: `1/2/3` → `S/M/L`
- `experience_level`: `0/1/2/3` → `EN/MI/SE/EX`
- `leadership`: `0/1` → `NonLead/Lead`

The **level order is unchanged**, so every estimate, standard error, t-ratio and
p-value is numerically identical to before — only the printed names change.
The factors are deliberately left *unordered*: `contr.sum` (set for the Type III
tests) applies to unordered factors, and an ordered factor would silently switch
to polynomial contrasts. The helper is idempotent, so re-sourcing it is safe.

When Step 1 is fixed later to emit labelled factors directly, this helper becomes
a no-op — it only relabels when it sees the exact integer-code level sets — so
the two changes will not conflict.

blocks in the comments were updated to match, and re-padded so their columns line
up with the real output again. **Only the labels changed — every estimate, SE,
df, t-ratio and p-value in those comments is unchanged and was re-verified
against the fresh run.**
