# Activity 1 Step 4 change log

## Scope

This change log covers Activity 1 Steps 1-4 only and is organized by step as
requested. `FinalProject_2026.md` was treated as authoritative. Activity 2, all
`task.md` files, and Activity 1 Steps 5-7 were not edited or executed.

## step1

### Changes

- Updated `activity1/step1/data_processing.R` to retain five non-modeling/support
  fields before the existing transformations:
  - `source_row_id` for traceability and split verification;
  - `observed_salary_in_usd` for an uncapped holdout response;
  - `employment_type_code`, `employee_residence_code`, and
    `company_location_code` for training-only categorical handling in Step 4.
- Corrected comments about duplicate independence, outlier handling, discarded
  management titles, and the actual role distribution.

  and must not be used by Step 4.
- Regenerated `activity1/dataset/cleaned_data.rds` through the Step 1 script. It
  now has 600 rows and 17 columns.
- Added `activity1/step1/summary.md`.

### Reason

The previous cleaned RDS contained only the full-data-winsorized salary, so Step
4 could not preserve an untouched test outcome. It also discarded the original
employment/location codes needed for training-only rare-level handling. The
support columns solve those Step 4 blockers without changing the legacy
variables consumed by Steps 2-3.

### Verification

- The saved RDS contains 600 unique source IDs and no missing required values.
- Joining by `source_row_id` verified exact equality between all four preserved
  raw fields and the source CSV.

  observed response retains the USD 600,000 maximum.
- Steps 2 and 3 completed successfully on the regenerated RDS, confirming that

- The legacy full-data-winsorized and standardized fields remain for Step 2/3

- The Step 1 script is working-directory dependent and its named PDFs are legacy

## step4

### Changes

- Added the sole Step 4 implementation file,
  `activity1/step4/continuous_salary_regression.R`.
- Added an 80/20 grouped, salary-quartile-stratified split with seed 6767.
  Identical modeling records stay together so no exact twin can cross the
  holdout.
- Added a training-fitted recipe that:
  - pools original employment/company-location levels below 2%;
  - handles missing and previously unseen nominal values;
  - creates treatment dummy variables;
  - removes zero-variance columns; and
  - normalizes work year from training data only.
- Treated remote ratio as a three-level categorical predictor rather than
  imposing a linear 0/50/100 effect.
- Excluded the legacy winsorized response, full-data standardized fields, and
  employee residence (the latter because of its strong association with company
  location).
- Fitted three continuous square-root-salary models: multiple linear
  regression, ridge regression, and LASSO regression.
- Tuned ridge and LASSO with seed-6768 10-fold grouped cross-validation using
  training data only and the same folds for both models.
- Added naive and empirical-smearing dollar back-transformations. Penalized
  smearing terms use grouped out-of-fold residuals and never use test outcomes.
- Added a synthetic missing/unseen-category bake test and executable assertions
  for schema, overlap, fold grouping, full rank, column alignment, finiteness,
  and nonnegative dollar predictions.
- Added `continuous_salary_models.rds`, containing the split, prepared recipe,
  folds, model objects, selected lambdas, smearing terms, modeling data, and
  held-out predictions.
- Added `model_training_summary.txt` and `activity1/step4/summary.md`.

### Reason

Step 4 was empty. The implementation supplies the required partition and more
than two appropriate continuous models while preventing the observed test
salary from influencing preprocessing, lambda selection, or back-transformation
parameters. It also provides a complete R-native handoff for later Step 6
evaluation without implementing that evaluation now.

### Verification

- Step 4 completed repeatedly with exit code 0 from the repository root.
- Exactly one `.R` file exists in `activity1/step4/`.
- Split: 480 training rows and 120 testing rows, with zero source-ID or
  duplicate-group overlap.
- Salary strata are balanced: training counts 120/121/124/115 and testing counts
  30/29/32/29 from lowest to highest quartile.
- Grouped tuning folds contain 47-50 rows each; every duplicate group occurs in
  exactly one fold.
- The baked matrix has 20 predictors, identical training/testing columns, no
  missing or infinite values, and a full-rank 21-parameter linear design
  including the intercept.
- Saved models have classes `lm`, `cv.glmnet`, and `cv.glmnet`.
- Selected 1-SE lambdas are 76.57622185 (ridge) and 8.02224563 (LASSO); LASSO has
  seven nonzero predictors at that penalty.
- All 120 held-out predictions are aligned to unique source IDs; corrected dollar
  predictions are finite and nonnegative.
- Two fresh end-to-end runs produced the same semantic SHA-256 fingerprint for
  split IDs, fold IDs, lambdas, and held-out predictions:
  `6c21fc1231eb3b939712c529b279dd25ff02d7f61b516bf91264c051e09deb39`.
- The script intentionally reports no RMSE, MAE, R-squared, model ranking, or
  best-model choice.

### Remaining issues

- Step 6 must evaluate the stored predictions on observed dollar salaries and
  select a model.
- The random stratified holdout estimates in-period generalization across
  2020-2022; it is not a true future-year forecast.
- The recipe is fitted on the full outer-training partition before `cv.glmnet`.
  This leaves the final test set completely untouched, but a stricter nested
  tuning design would re-fit rare-level pooling and normalization inside each
  inner analysis fold.
- Grouped out-of-fold smearing for penalized models is conservative because it
  includes fold-level model-estimation error.
